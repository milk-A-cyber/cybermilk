1.1 数据生成

基于新生数据（DeepSeek 合成）讲解异步加载与字段映射

Explains asynchronous loading and field mapping using the new-student dataset (synthesized by DeepSeek)

你的原案例

Your Original Case

本章采用中国石油大学（华东）2025 级新生数据，阐述数据的特性。为了防止数据隐私泄露，数据采用 DeepSeek 大模型生成。数据文件 data/newstudent.csv，含 80 条记录。

This chapter uses the 2025 new-student data from China University of Petroleum (East China) to illustrate the characteristics of data. To prevent data privacy leaks, the data was generated by the DeepSeek large language model. The data file data/newstudent.csv contains 80 records.

嵌入理论：AI 合成数据的可信度边界

Embedded Theory: The Trustworthiness Boundary of AI-Synthesized Data

数据质量四维度（Wang & Strong 1996）：准确性 / 完整性 / 一致性 / 时效性。

Four Dimensions of Data Quality (Wang & Strong 1996): Accuracy / Completeness / Consistency / Timeliness.

DeepSeek 生成数据：

Data Generated by DeepSeek:

  • ✅ 完整性：字段齐全
  • ✅ Completeness: all fields present
  • ⚠️ 准确性：姓名/籍贯是虚构的，不能用作真实人口分析
  • ⚠️ Accuracy: names/hometowns are fictional and cannot be used for real demographic analysis
  • ⚠️ 采样偏差：模型倾向"看起来合理"的分布（如民族偏汉族、籍贯偏大城市）
  • ⚠️ Sampling bias: the model tends toward 'plausible-looking' distributions (e.g., over-representing the Han ethnicity, favoring large cities for hometowns)

课堂要点：教学场景使用合成数据没问题，但必须标注"合成数据"，避免学生误以为真实分布。

Classroom Takeaway: Using synthetic data in teaching is fine, but it must be labeled as 'synthetic data' to prevent students from mistaking it for a real distribution.

数据流水线：CSV → 可绑定数据Data Pipeline: CSV → Bindable Data悬停步骤看说明Hover a step

① CSV 文件：原始文本，字段名是中文 —— 序号 / 姓名 / 性别 / 生日 / 年龄 / 班级。 ① CSV File: raw text with Chinese column names — id / name / gender / birthday / age / class. ② 异步加载：d3.csv(路径) 不阻塞页面渲染，返回 Promise，必须 await。 ② Async Load: d3.csv(path) does not block rendering, returns a Promise and must be awaited. ③ 字段映射：中文列名 → 英文变量名，避免 JS 语法 / 编码 / 工具链隐患。 ③ Field Map: Chinese column names → English variables, avoiding JS syntax / encoding / toolchain issues. ④ 类型转换：字符串 → Number / Date（一元 + 与 new Date / d3.timeParse）。 ④ Type Cast: strings → Number / Date (unary +, new Date / d3.timeParse). ⑤ 可绑定数组：得到干净的转换后数组，直接供 D3 做 data-join 可视化。 ⑤ Bind Array: a clean transformed array, ready for D3 data-join visualization.

关键代码 ① 字段名映射

Key Code ① Field Name Mapping

中文列名映射成英文变量名 —— 避免 JS 中带中文 key 引发语法/编码隐患。

Map Chinese column names to English variable names — to avoid syntax/encoding issues caused by Chinese keys in JS.

⭐ // 关键点 ①：字段映射 —— 中文 → 英文
const COLUMN_MAP = {
  "序号": "id",
  "姓名": "name",
  "性别": "gender",
  "生日": "birthday",
  "年龄": "age",
  "班级": "class",
};

关键点解释：为什么不用中文 key？ (1) JS 引擎对中文标识符的容错性差（老浏览器报错）；(2) 后端、JSON、URL 编码都可能引入乱码； (3) IDE 自动补全、搜索、重构工具对中文支持不一致。 最佳实践：CSV 用人可读的中文名，JS 内部统一英文变量。

Key-Point Explanation: Why not use Chinese keys? (1) JS engines have poor tolerance for Chinese identifiers (older browsers throw errors); (2) backends, JSON, and URL encoding may introduce mojibake; (3) IDE autocomplete, search, and refactoring tools have inconsistent support for Chinese. Best Practice: Use human-readable Chinese names in CSV, and use unified English variables internally in JS.

关键代码 ② 类型转换函数

Key Code ② Type Conversion Functions

CSV 加载后所有字段都是字符串，需要把序号/年龄 → Number，生日 → Date 对象。

After CSV loading, all fields are strings; you need to convert the index/age to Number and the birthday to a Date object.

⭐ // 关键点 ②：类型转换函数 —— 用户原文「推荐方式」
function transformRow(d) {
  return {
    id:       +d["序号"],              // 一元 + 把字符串转 Number
    name:     d["姓名"].trim(),       // trim() 去掉首尾空白
    birthday: new Date(d["生日"]), // 字符串 → Date 对象
    age:      +d["年龄"],
    class:    d["班级"].trim(),
  };
}

关键点解释： +d["年龄"] 是一元加运算符，是 JS 里把字符串转数字的最快写法（比 Number() / parseInt() 都短）； new Date(str) 能解析 "2007-08-15" 这类 ISO 格式，但对 "2007/8/15" 兼容性差，要用 d3.timeParse("%Y-%m-%d") 兜底。 坑：没有 trim() 的话，"软件工程1班 " 里的空格会让后续过滤/聚合出错。

Key-Point Explanation: +d["年龄"] is the unary plus operator, the fastest way in JS to convert a string to a number (shorter than Number() / parseInt()); new Date(str) can parse ISO formats like "2007-08-15", but has poor compatibility with "2007/8/15", so fall back to d3.timeParse("%Y-%m-%d"). Pitfall: Without trim(), the trailing space in "软件工程1班 " will cause later filtering/aggregation to fail.

关键代码 ③ d3.csv 第二参直接传 row 回调

Key Code ③ Pass the row callback directly as the second argument of d3.csv

⭐ // 关键点 ③：一行完成加载 + 转换（用户原文「代码示例 1」）
const data = await d3.csv("data/newstudent.csv", transformRow);

// 验证类型确实转换了：
console.log(typeof data[0].age);        // "number"
console.log(data[0].birthday instanceof Date); // true

关键点解释：d3.csv 是异步函数，必须 await。 第二参的 row 回调会在每一行解析后立即调用——比先 await d3.csv(...) 再 .map(transformRow) 更省内存（边读边转）。 异步加载的意义：不阻塞页面渲染，用户能继续交互。

Key-Point Explanation: d3.csv is an asynchronous function and must be awaited. The row callback in the second argument is invoked immediately after each row is parsed — which saves memory compared to first await d3.csv(...) then .map(transformRow) (transform while reading). Significance of Asynchronous Loading: It does not block page rendering, so the user can keep interacting.

1.2 数据定义

DIKW 金字塔 —— 数据 → 信息 → 知识 → 智慧

DIKW Pyramid — Data → Information → Knowledge → Wisdom

你的原案例

Your Original Case

DI 金 W 金字塔：数据是"原始原始数据"，信息是"组织好的数据"，知识是"模式/规律"，智慧是"判断/战略"。

DIKW Pyramid: Data is 'raw data', Information is 'organized data', Knowledge is 'patterns/regularities', and Wisdom is 'judgment/strategy'.

层原文回答的问题
数据原始、离散的观察结果—
信息经过处理、组织、赋予上下文的数据谁 / 什么 / 何时 / 何地
知识对信息的进一步提炼和理解如何
智慧运用知识做出明智判断和战略决策为什么 / 应该怎么做
TierTermQuestion Answered
DataRaw, discrete observations—
InformationData that has been processed, organized, and given contextWho / What / When / Where
KnowledgeFurther refinement and understanding of informationHow
WisdomApplying knowledge to make wise judgments and strategic decisionsWhy / What to do

嵌入理论：可视化在 DIKW 中的位置

Embedded Theory: The Position of Visualization in the DIKW Model

关键洞见：可视化主要把 Data 升到 Information，少数场景能升到 Knowledge，但难以跨越到 Wisdom。

Key Insight: Visualization mainly lifts Data to Information; in a few scenarios it can reach Knowledge, but it is difficult to cross over to Wisdom.

  • ✅ Data → Information：把表格"翻译"成可读图形（折线图、柱状图、热图）
  • ✅ Data → Information: 'Translate' the table into readable graphics (line chart, bar chart, heatmap)
  • ⚠️ Information → Knowledge：模式发现需要统计模型辅助（机器学习）
  • ⚠️ Information → Knowledge: Pattern discovery requires statistical models (machine learning)
  • ❌ Knowledge → Wisdom：决策与战略超出可视化能力
  • ❌ Knowledge → Wisdom: Decisions and strategy are beyond the capability of visualization

Rowley (2007) 批评：DIKW 是过度简化的层次模型，现实中 Data 与 Information 的界限模糊。但作为教学脚手架，仍然最有价值。

Rowley (2007) Critique: DIKW is an oversimplified hierarchical model; in reality the boundary between Data and Information is blurred. But as a teaching scaffold, it remains most valuable.

可视化能力边界阶梯（DIKW）Viz Capability Ladder (DIKW)点击行查看详情Click a row

✅ 可胜任：折线图 / 柱状图 / 热图把表格「翻译」成可读图形，回答 谁 · 什么 · 何时 · 何地。 ✅ Capable: line/bar/heatmaps translate tables into readable graphics, answering Who · What · When · Where. ⚠️ 有限：从图中「发现规律」需要统计模型与机器学习辅助，可视化只提供线索。 ⚠️ Limited: finding patterns needs statistical models and ML; visualization only provides clues. ❌ 不可以：做判断与战略决策超出可视化能力范围，必须由人脑完成。 ❌ Cannot: judgment and strategic decisions go beyond visualization — they stay with the human.

关键代码 ① SVG 金字塔路径

Key Code ① SVG Pyramid Path

金字塔由 4 个 trapezoid 拼接而成 —— D3 path 的 d 属性。

The pyramid is composed of 4 trapezoids joined together — the d attribute of the D3 path.

⭐ // 关键点 ①：trapezoid 路径 —— 从上到下 4 个点的连线
const topW = 60, botW = 120;
const yTop = 20, yBot = 100;
const path = `
  M ${cx - topW/2} ${yTop}
  L ${cx + topW/2} ${yTop}
  L ${cx + botW/2} ${yBot}
  L ${cx - botW/2} ${yBot}
  Z
`;

关键点解释：SVG path 的 M(moveto)、L(lineto)、Z(close) 是 3 个最常用指令。 模板字符串 `${...}` 可以直接嵌入 JS 变量，比字符串拼接更可读。 实践：复杂形状用 D3 的 d3.symbol()（内置 ★●▲ 等），自己 path 容易出错。

Key-Point Explanation: The SVG path commands M (moveto), L (lineto), and Z (close) are the three most commonly used. Template literals `${...}` can embed JS variables directly, making them more readable than string concatenation. Practice: For complex shapes, use D3's d3.symbol() (which has built-in ★●▲ etc.); hand-writing paths is error-prone.

关键代码 ② 交互高亮（hover/click）

Key Code ② Interactive Highlighting (hover/click)

⭐ // 关键点 ②：选择集绑定事件 —— D3 的事件模型
const g = svg.append("g")
  .style("cursor", "pointer")
  .on("mouseover", function() {       // 注意 function 而非箭头函数
    d3.select(this).select("path")
       .transition().duration(150)
       .attr("fill", d3.color(layer.color).brighter(0.5));
  })
  .on("click", () => showDetail(layer));

关键点解释：必须用 function() 而非箭头函数—— 因为 D3 回调里要用 this 访问当前元素，箭头函数会捕获外层 this 导致失效。这是 D3 最常见的坑。 transition().duration() 是 D3 内置动画 API，比 jQuery 还简洁。

Key-Point Explanation: You must use function() instead of arrow functions — because D3 callbacks use this to access the current element, and arrow functions capture the outer this, causing it to fail. This is the most common D3 pitfall. transition().duration() is D3's built-in animation API, even more concise than jQuery.

1.3 数据属性

Stevens 测量尺度 × Mackinlay 视觉通道排序

Stevens Measurement Scales × Mackinlay Visual Channel Ranking

你的原案例（3 大类）

Your Original Case (3 Categories)

你的原文给出 3 类属性：

Your original text gives 3 types of attributes:

  • 类别型属性：符号或名称，无顺序关系（性别、姓名）
  • Categorical Attribute: a symbol or name with no ordering (gender, name)
  • 序数型属性：属性值有顺序（学位：本科/硕士/博士）
  • Ordinal Attribute: attribute values have an order (degree: bachelor's/master's/doctorate)
  • 数值型属性：定量方法（年龄、价格）
  • Numerical Attribute: quantitative method (age, price)

Stevens divides measurement scales into 4 types, finer than your original text:

Mackinlay proposes dividing visual channels into 3 tiers:

Core Finding: Position is the strongest quantitative channel; hue is the strongest qualitative channel. Mismatch → information loss.

① 名义 Nominal：只能判断 相等 / 不等（= ≠），如姓名、性别。 ① Nominal: only equivalence/non-equivalence (= ≠), e.g. name, gender. ② 序数 Ordinal：增加 排序（< >），如学位、班级排名。 ② Ordinal: adds ordering (< >), e.g. degree, class rank. ③ 区间 Interval：增加 加减（+ −），如温度 °C —— 但 无真零点（0°C ≠ 没有温度）。 ③ Interval: adds add/subtract (+ −), e.g. °C — but no true zero (0°C ≠ no temperature). ④ 比率 Ratio：增加 乘除（× ÷），有 真零点，如年龄、价格。 ④ Ratio: adds multiply/divide (× ÷) with a true zero, e.g. age, price.

Mackinlay 定量通道排序（节选）Mackinlay Quantitative Channel Ranking (excerpt)悬停看说明Hover a bar

1st 位置：最强的定量通道，人眼最先读取坐标 —— 散点图 / 折线图的基础。 1st Position: strongest quantitative channel; the eye reads coordinates first — basis of scatter/line charts. 2nd 长度：条形图的原理，读数直观准确。 2nd Length: the principle behind bar charts; accurate to read. 3rd 角度：饼图 / 极坐标图依赖角度判断。 3rd Angle: pie/polar charts rely on angle judgment. 4th 面积：弱于长度 —— 面积感知是非线性的（气泡图常被高估）。 4th Area: weaker than length — area perception is non-linear (bubble charts are overestimated). 5th 亮度/饱和度：能表达顺序，但不精确，适合做层级补充。 5th Brightness/Saturation: conveys order but not precise; good as secondary encoding. 6th 色相：本质是定性通道，编码数值感知差。 6th Hue: essentially a qualitative channel — poor for encoding quantity. 7th 密度：纹理疏密可表达顺序，精度有限。 7th Density: texture coarseness conveys order with limited precision. 8th 形状：只适合分类，定量感知最弱。 8th Shape: suited only for categories — weakest for quantity.

关键代码 ① map / reduce 的链式组合

Key Code ① Chained Composition of map / reduce

⭐ // 关键点 ①：函数式数据流 —— map 后接 filter 再 reduce

  students
    .filter(s => s.gender === "男")    // ① 过滤男生

嵌入理论：Data-Join 三态模型（Mike Bostock）

Embedded Theory: The Data-Join Three-State Model (Mike Bostock)

D3 的核心是 Data-Join：把数据数组"绑定"到 DOM 元素上。

The core of D3 is Data-Join: 'binding' a data array to DOM elements.

当数据变化时：

When the data changes:

  • 新数据 > 旧数据：多出来的进入 enter（要 append）
  • New data > old data: the extras enter enter (need to append)
  • 新数据 = 旧数据：原有元素进入 update（要改属性）
  • New data = old data: the existing elements enter update (need attribute changes)
  • 新数据 < 旧数据：多余的元素进入 exit（要 remove）
  • New data < old data: the surplus elements enter exit (need to remove)

Data-Join 三态泳道Data-Join Three-State Swimlane方块 = 数据，圆圈 = DOM 元素Squares = data, circles = DOM elements

数据与 DOM 绑定时按三种情况分流：多 → enter（新建元素），等 → update（改属性），少 → exit（移除）。 Binding data to DOM splits into three cases: more → enter (append), equal → update (change attrs), fewer → exit (remove). enter：新数据比旧 DOM 多 2 个 → 多出的 append() 新建；原有的 1–3 继续 update。 enter: 2 more data than DOM → extra items are append()-ed; existing 1–3 stay in update. update：数据与 DOM 数量相等（3 = 3）→ 一一配对，只更新属性 / 内容，不重建节点。 update: data equals DOM (3 = 3) → one-to-one matching; only attributes/content change, no rebuild. exit：数据比 DOM 少 2 个 → 多出的 DOM 元素 remove() 移除。 exit: 2 fewer data than DOM → surplus DOM elements are remove()-d.

关键代码 ① .join(enter, update, exit) 三态

Key Code ① .join(enter, update, exit) Three States

关键代码 ② key 函数保身份

⭐ // 关键点 ②：key 函数 —— 元素身份的稳定器

关键代码 ③ d3.select vs d3.selectAll

Key Code ③ d3.select vs d3.selectAll
