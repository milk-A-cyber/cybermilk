4.1 数据转换

你的 Crime 数据是宽格式，可视化常需要长格式。转换函数一行解决。

Your Crime data is in wide format, but visualization often needs long format. A one-liner conversion function handles it.

🎨 本节使用了 colormap（Viridis）画热图。colormap 理论详见 第 3 章 3.2 colormap 三类选择。

你的原案例

Your Original Case

原 5.1 节用了 1985 美国 50 州犯罪数据（CSV），含 8 个犯罪指标列。

Section 5.1 used 1985 U.S. crime data (CSV) for the 50 states, with 8 crime-indicator columns.

嵌入陈为教材理论

Embedded Theory

  • 长格式（long）：每行一个观测，列 = 字段（如 {state, metric, value}）。优点：方便过滤、分组、绑定到 d3 join。
  • Long format (long): one observation per row, columns = fields (e.g., {state, metric, value}). Pros: easy to filter, group, and bind to a d3 join.
  • 宽格式（wide）：每行一个实体，列 = 指标（如 {state, murder, robbery, ...}）。优点：人眼读得懂、直观。
  • Wide format (wide): one entity per row, columns = metrics (e.g., {state, murder, robbery, ...}). Pros: human-readable and intuitive.
  • 转换：flatMap + 循环键名 = 几行代码搞定。
  • Conversion: flatMap + iterating over key names = a few lines of code.
  • d3.autoType：自动推断列类型（数字、日期、布尔），省得手动 +d.field。
  • d3.autoType: auto-infers column types (number, date, boolean), saving you from manual +d.field.

flatMap 展开：一行 wide（Alabama 一行 12 列）拆成 3 个观测 {state, metric, value} —— 每行一个观测，可直接 d3.group / filter / 绑定 data-join。 flatMap split: one wide row (Alabama, 12 columns) becomes 3 observations {state, metric, value} — one observation per row, ready for d3.group / filter / data-join. 宽格式：一个实体（州）占一行，指标挤成 12 列 —— 人眼友好，但机器分组 / 过滤麻烦。 Wide format: one entity (state) per row, 12 metric columns — human-friendly but awkward to group / filter programmatically.

4.2 坐标轴变换

数据空间 → 坐标系空间 → 屏幕空间。三层职责分明，错了就乱套。

Data space → coordinate system space → screen space. Three layers with clearly separated responsibilities; mix them up and everything falls apart.

你的原案例

Your Original Case

原 5.1.2 节用散点展示 Crime 数据（murder vs robbery），坐标轴是 1985 数据。

Section 5.1.2 used a scatter plot to display Crime data (murder vs. robbery), with the 1985 data on the coordinate axes.

嵌入陈为教材理论

Embedded Theory

  • 三层空间：
    1. 数据空间：原始数值（如人口 27058000、谋杀率 8）
    2. 坐标系空间：归一化到 0..innerWidth（标准化坐标）
    3. 屏幕空间：加上 margin 偏移（最终像素位置）
  • Three-layer space:
    1. Data Space: raw values (e.g., population 27058000, murder rate 8)
    2. Coordinate Space: normalized to 0..innerWidth (standardized coordinates)
    3. Screen Space: add the margin offset (final pixel positions)
  • 为什么分层：坐标系空间内的元素（线、点）可以共享，切换屏幕尺寸时无需重算。d3.axisBottom 自动帮你做坐标系→屏幕。
  • Why layer them: elements inside the coordinate system space (lines, points) can be shared — no recalculation when the screen size changes. d3.axisBottom handles the coordinate-system → screen step automatically.
  • scale 选型：
    • scaleLinear：均匀分布，最常用
    • scaleLog：跨数量级（人口从 53 万到 2700 万）
    • scaleSqrt：面积感知（圆面积映射到值）
    • scaleBand：类别轴（柱状图）
  • Scale selection:
    • scaleLinear: uniform distribution, most common
    • scaleLog: spans orders of magnitude (population from 530k to 27M)
    • scaleSqrt: area-aware (maps circle area to value)
    • scaleBand: categorical axis (bar charts)

三层坐标变换：数据 → 坐标系 → 屏幕Three Layers: Data → Coordinate → Screen用步进按钮逐层点亮Step through the layers

① 数据空间只存原始数值（人口 27,058,000），不知道屏幕多大。 ① Data space stores the raw value (population 27,058,000); it knows nothing about the screen. ② xData 把值压到 [0, innerW] —— 坐标系空间内元素可复用，屏幕变大不用重算。 ② xData squeezes values into [0, innerW] — elements in coordinate space are reusable when the screen size changes. ③ xScreen 再加 margin 偏移（+50）得最终像素位；渲染时 .attr('cx', xScreen(xData(d.x)))。 ③ xScreen adds the margin offset (+50) to get final pixels; render with .attr('cx', xScreen(xData(d.x))).

  • 三层空间各存什么？What does each of the three spaces hold?
    数据空间存原始值；坐标系空间归一化到 [0, innerW]；屏幕空间加 margin 得像素位。Data space: raw values; coordinate space: normalized to [0, innerW]; screen space: pixels after adding the margin.

    跨数量级（53 万 ~ 2700 万，约 50 倍）：人眼按比例感知，log 让等比数列在屏幕上等距。It spans orders of magnitude (530k–27M, ~50×): the eye perceives ratios, so log keeps geometric sequences equally spaced.

⭐ 关键代码

★ Key Code

⭐ 关键点 1：数据空间 vs 屏幕空间，两层 scale

★ Key Point 1: data space vs. screen space — two layers of scales

// 数据空间：值 → 坐标系
const xData = d3.scaleLinear()
  .domain([0, d3.max(data, d => d.x)])
  .range([0, innerW]);

// 屏幕空间：坐标系 → 屏幕（加 margin）
const xScreen = d3.scaleLinear()
  .domain([0, innerW])
  .range([M.l, M.l + innerW]);

// 渲染：数据 → 坐标系 → 屏幕
.attr('cx', d => xScreen(xData(d.x)))

⭐ 错位示范：直接把 domain/max 和 range/[M.l, M.l+innerW] 写在一个 scale 里 → 改 margin 要改两处。三层分立就清爽。

★ Misalignment example: writing domain=max and range=[M.l, M.l+innerW] in one scale → changing the margin means editing two places. The three-layer separation keeps things clean.

⭐ 关键点 2：log scale 跨数量级

★ Key Point 2: log scale spans orders of magnitude

// 50 州人口从 53 万到 2700 万（差 50 倍）
// linear 缩放下，小州挤成一团，CA/NY/TX 占满屏幕
const xLog = d3.scaleLog()
  .domain([1, d3.max(data, d => d.x)])
  .range([0, innerW]);

⭐ log 轴对"指数增长"数据特别合适。人的视觉是"乘法"而不是"加法"，所以 log 让"等比数列"在屏幕上"等距"。

★ A log axis is especially well-suited for “exponential growth” data. Human vision is “multiplicative” rather than “additive”, so log turns a “geometric sequence” into “equally-spaced” points on screen.

数据空间 → 坐标系空间 → 屏幕空间。每一层职责不同，错位就会出问题。

4.3 曲线拟合

同 50 个点，用 10 种 line.curve 画风各异。什么时候用哪种？

Same 50 points, 10 different line.curve styles. Which to use when?

你的原案例

Your Original Case

原 5.1.3 节用折线 + 散点展示趋势。原始代码用了 curveCatmullRom，没讲为什么。

Section 5.1.3 used a line + scatter plot to show trends. The original code used curveCatmullRom without explaining why.

嵌入陈为教材理论

Embedded Theory

  • 插值 vs 拟合：
    • 插值（interpolation）：曲线经过所有数据点（如 Catmull-Rom、Natural）
    • 拟合（fitting）：曲线不经过数据点，只反映趋势（如线性回归 LOESS）
  • Interpolation vs. Fitting:
    • Interpolation: the curve passes through every data point (e.g., Catmull-Rom, Natural)
    • Fitting: the curve does not necessarily pass through data points, only reflects the trend (e.g., linear regression, LOESS)
  • d3.line().curve() 提供 10+ 种 curve，最常用：
  • d3.line().curve() offers 10+ curves; the most commonly used are:
  • step 系：用于离散阶跃（数字信号、状态切换）
  • step family: for discrete steps (digital signals, state transitions)
  • catmullRom / natural：过所有点的张力样条，"看起来平滑"
  • catmullRom / natural: tension splines that pass through all points — “looks smooth”
  • monotoneX：保持原数据序列单调（不会出现伪震荡）
  • monotoneX: preserves the monotonicity of the original data sequence (no spurious oscillations)
  • 选择原则：数据有顺序性 → monotoneX / linear；数据本身抖动大 → catmullRom / basis 平滑；离散状态 → step
  • Selection principles: ordered data → monotoneX / linear; jittery data → catmullRom / basis to smooth; discrete states → step

⭐ 关键点 2：拟合 vs 插值的取舍

★ Key Point 2: the trade-off between fitting and interpolation

// 拟合：d3.regressionLinear / d3.regressionLoess

  .x(d => d.population)
  .y(d => d.murder)

4.4 倾角感知（45° 黄金角）

人眼对斜率的估计 不是 线性的。45° 是视觉"中点"。

Human perception of slope is not linear. 45° is the visual “midpoint”.

你的原案例

Your Original Case

原 5.1.4 节提到"平均倾斜度最优为 45°"，但没解释原因。

Section 5.1.4 mentions that “the optimal average slope is 45°” without explaining why.

嵌入陈为教材理论

Embedded Theory

  • Cleveland 1984 实验：让被试估计直线的斜率，发现：
    • 斜率 = 0° 或 90° 时，估计误差最大
    • 斜率 = 45° 时，估计最准
    • 呈 U 型曲线
  • Cleveland 1984 experiment: subjects were asked to estimate line slopes:
    • Slope = 0° or 90°: estimation error is largest
    • Slope = 45°: estimation is most accurate
    • The error curve is U-shaped
  • Stevens 幂律：感知斜率 ≈ (真实斜率)^1.0 ~ 1.3。即人眼把"陡度"夸张了 30%。
  • Stevens’ power law: perceived slope ≈ (actual slope)1.0–1.3. In other words, the eye exaggerates “steepness” by about 30%.
  • 设计原则：
    • 关键数据斜率落在 30°~60° 区间最稳
    • 对比增长曲线时，用 log 轴让陡度落在 45° 左右
    • 避免在 5° 以下或 85° 以上做趋势对比（误差太大）
  • Design principles:
    • Key data slopes are most stable in the 30°–60° range
    • When comparing growth curves, use a log axis so steepness lands near 45°
    • Avoid trend comparisons below 5° or above 85° (errors grow too large)

45°

30°–60° 区间：斜率最稳 —— Cleveland 实验中人眼在此区间估计最准。 The 30°–60° range: slopes are most stable — subjects estimate them most accurately there. 太缓（<30°）：感知偏差被放大，越接近 0° 误差越大。 Too shallow (<30°): perceived bias grows; the closer to 0°, the larger the error. 太陡（>60°）：接近 90° 时误差同样被放大。 Too steep (>60°): error grows again near 90°.

⭐ 关键点 1：极坐标转笛卡尔坐标

★ Key Point 1: convert polar to Cartesian coordinates

// 角度 → 屏幕坐标
function lineAtAngle(angleDeg, length = 240, origin = {x: 100, y: 240}) {
  const r = (angleDeg * Math.PI) / 180;
  return {
    x1: origin.x,
    y1: origin.y,
    x2: origin.x + length * Math.cos(r),
    y2: origin.y - length * Math.sin(r)   // SVG y 向下为正，所以取负
  };
}

⭐ SVG 的 y 轴向下（与数学相反），所以 sin 角度项要取负。这是初学者最常踩的坑。

★ SVG’s y axis points downward (opposite to math convention), so the sine term must be negated. This is the most common pitfall for beginners.

📘 倾角感知（Cleveland 1984）

人眼对斜率的感知 不是 线性。Cleveland 1984 实验：45° 倾角 是"看上去差距最小、最接近真实值"的角度。

45°

⭐ 关键点

  • Stevens 幂律：斜率感知 ≈ (真实斜率)^1.0 ~ 1.3 区间
  • 45° 是视觉"中点"：人眼对靠近 45° 的斜率估计最准
  • 设计图表时：让关键数据斜率落在 30°-60°，避免在 0° 或 90° 附近做趋势对比
  • 例：增长曲线若是指数增长，前期很缓、后期很陡，应换 log 轴让斜率落在 ~45°

Embedded Theory

  • Marching Squares 原理：把标量场离散化为网格，每个 cell 4 个角的"是否大于阈值"决定 case 编号 0~15（2⁴=16 种）。每种 case 对应 0/1/2 条线段，把"超过阈值"和"未超过阈值"的两片区域分开。
  • How Marching Squares works: discretize the scalar field into a grid. For each cell, the “above threshold / not” state of its 4 corners yields a case index from 0 to 15 (24 = 16 cases). Each case corresponds to 0, 1, or 2 line segments that separate the “above-threshold” region from the “not” region.
  • 16 种 case：编码 bit0=BL、bit1=BR、bit2=TR、bit3=TL。
  • 16 cases: encoded as bit0=BL, bit1=BR, bit2=TR, bit3=TL.
  • 扩展到 3D：Marching Cubes（Lorensen & Cline 1987），2⁸=256 种 case，常用于医学 MRI / CT 等值面提取。
  • Extension to 3D: Marching Cubes (Lorensen & Cline, 1987), with 28 = 256 cases, widely used for extracting isosurfaces from medical MRI / CT scans.
  • 应用场景：
    • 地形等高线（地图）
    • 医学影像（MRI/CT 等值面）
    • 密度等高图（核密度估计）
    • 天气预报（等温线、等压线）
  • Application scenarios:
    • Terrain contour lines (maps)
    • Medical imaging (MRI / CT isosurfaces)
    • Density contours (kernel density estimation)
    • Weather forecasting (isotherms, isobars)

★ Key Code

⭐ 关键点 1：16 case lookup table（核心数据结构）

★ Key Point 1: the 16-case lookup table (core data structure)

// ⭐ 16 种 case 每种对应 0/1/2 条线段（用边的编号表示）
// 边编号：0=左中, 1=下中, 2=右中, 3=上中
const EDGE_TABLE = [
  [],                  // 0000 全小
  [[3, 0]],            // 0001 仅 BL 大
  [[0, 1]],            // 0010 仅 BR 大
  [[3, 1]],            // 0011 BL+BR
  [[1, 2]],            // 0100 仅 TR 大
  [[3, 0], [1, 2]],    // 0101（saddle 鞍点，需）
  [[0, 2]],            // 0110 BR+TR
  [[3, 2]],            // 0111
  [[2, 3]],            // 1000 仅 TL 大
  [[2, 0]],            // 1001 TL+BL
  [[0, 1], [2, 3]],    // 1010（saddle）
  [[2, 1]],
  [[1, 3]],
  [[1, 0]],
  [[0, 3]],
  []                   // 1111 全大
];

⭐ saddle case（5 和 10）是 Marching Squares 唯一需要"判断中心值"的歧义情况——其它 14 种 case 一查表就出。Saddle 用 cell 中心点对比阈值决定连线方向。

★ The saddle case (5 and 10) is the only ambiguous situation in Marching Squares that requires “checking the center value” — the other 14 cases are resolved with a simple lookup. For saddle cases, compare the cell center to the threshold to decide how to connect the line segments.

⭐ 关键点 2：位运算拼 case 编号

★ Key Point 2: assemble the case index with bitwise operations

// 4 个角是否 > 阈值 → 4 位二进制 → case 编号
let code = 0;
if (bl > threshold) code |= 1;   // bit 0
if (br > threshold) code |= 2;   // bit 1
if (tr > threshold) code |= 4;   // bit 2
if (tl > threshold) code |= 8;   // bit 3

const lines = EDGE_TABLE[code];   // 查表
