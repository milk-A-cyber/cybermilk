1.1布局设计流程Layout Design Workflow

先规划、后实现：从需求到线框图，再落到代码

Plan first, then build: from requirements to wireframes, then to code

你的贯穿案例

Your Running Case

全章案例是「拾味山居」美食旅行博客的首页。它的任务很明确：让访客在 3 秒内知道这是什么网站、今天有什么新内容、可以从哪里进入。所有章节都会围绕这个页面展开。

The running case of this chapter is the homepage of “Shiwei Mountain House”, a food & travel blog. Its mission is clear: let visitors know within 3 seconds what this site is, what is new today, and where to go next. Every section revolves around this page.

布局设计的五步流程

The Five-Step Layout Workflow

  1. 明确需求与目标：给谁看、要达成什么。本例 = 内容型博客，重点是“读”，不是“买”。
  2. Clarify requirements & goals: for whom, and to achieve what. This case = a content blog, focused on “reading”, not “buying”.
  3. 信息架构（IA）：把内容分组并排序 —— 导航、首屏、栏目、文章列表、页脚。
  4. Information architecture (IA): group and order content — nav, hero, sections, article list, footer.
  5. 线框图（Wireframe）：用灰块画出每一块内容的位置与大小，只谈结构，不谈样式。
  6. Wireframe: draw the position and size of every block with grey boxes — structure only, no styling.
  7. 视觉设计：在线框上加字体、色彩、间距，确定层级与情绪。
  8. Visual design: add typography, color, and spacing on the wireframe; settle hierarchy and mood.
  9. 代码实现：把定稿的结构翻译成语义化 HTML 与 CSS 布局。
  10. Implementation: translate the approved structure into semantic HTML and CSS layout.

嵌入理论：为什么必须“先线框后代码”

Embedded Theory: Why Wireframe Before Code

  • 返工成本曲线：改线框只需 5 分钟，改写好的页面需要数小时。结构错误越晚发现，修复越贵。
  • The rework cost curve: fixing a wireframe takes 5 minutes; fixing a finished page takes hours. The later a structural flaw is found, the more expensive it is.
  • 聚焦结构：线框刻意“丑”，因为样式会干扰你对布局的判断（这也是本页所有演示都用灰块的原因）。
  • Focus on structure: wireframes are intentionally “ugly”, because styling distracts your judgment about layout (which is why every demo on this page uses grey blocks).
  • 心智模型：用户对页面有既有期待（导航在顶部、页脚在最底）。线框帮你检查 IA 是否符合直觉。
  • Mental model: users already expect certain conventions (nav on top, footer at the bottom). Wireframes help you check whether your IA matches intuition.

课堂要点：新手最常见的错误是跳过线框直接写代码，于是“边写边想结构”，反复重构。先花 10 分钟画线框，能省下 2 小时返工。Classroom takeaway:The most common beginner mistake is skipping the wireframe and coding directly, “thinking about structure while writing”, then refactoring repeatedly. Ten minutes of wireframing saves two hours of rework.

关键代码 ① 线框 → 语义化骨架

Key Code ① Wireframe → Semantic Skeleton

线框的每个灰块，对应一个语义标签。命名区域（grid-template-areas）让整个页面结构一眼可读。

Every grey block in the wireframe maps to a semantic tag. Named areas (grid-template-areas) make the whole page structure readable at a glance.

/* 用 grid-template-areas 描述宏观布局：线框 → 代码一一对应 */
.page{
  display: grid;
  grid-template-areas:
    "nav   nav"
    "hero  hero"
    "feat  feat"
    "posts posts"
    "footer footer";
  grid-template-columns: 1fr 1fr;
  max-width: 1200px;
  margin-inline: auto;  /* 容器水平居中 */
}

关键点解释：CSS Grid 的 grid-template-areas 让你用“名字”描述整页布局，和线框图同构；改结构时只改这一处，不用数浮动或边距。Key point:grid-template-areas lets you describe the whole page by “names”, isomorphic to the wireframe; restructuring only touches this one block — no floats or margins to count.

关键代码 ② 从线框到首屏（hero）

Key Code ② From Wireframe to the Hero

同一块内容，先有结构再有样式：语义容器 + 少量样式即可成型。

The same content: structure first, then style — a semantic container plus a little CSS makes it real.

<section class="hero">
  <h1>山里的味道，值得慢慢走</h1>
  <p>记录每一道菜与它背后的地方。</p>
  <a class="btn" href="#posts">开始阅读</a>
</section>

关键点解释：先用 HTML 把“内容层级”写对（h1 → p → a），CSS 只负责把它们放在页面上的位置。结构对了，样式只是锦上添花。Key point:First get the content hierarchy right in HTML (h1 → p → a); CSS only positions them on the page. Right structure makes styling a bonus, not a rescue.

1.2六大设计原则Six Core Design Principles

层级、对齐、对比、亲密性、留白、一致性 —— 布局质量的检查清单

Hierarchy, Alignment, Contrast, Proximity, Whitespace, Consistency — the checklist for layout quality

Six Principles, Memorized at Once

嵌入理论：格式塔原理（Gestalt）

Embedded Theory: Gestalt Principles

这六条原则的心理学根基是格式塔原理——大脑会把“接近、相似、闭合”的元素自动组织成整体：

The psychological foundation of these six principles is Gestalt theory — the brain automatically organizes elements that are close, similar, or enclosed into wholes:

  • 邻近律（Proximity）：距离近的元素被视为一组 → 支撑“亲密性”。
  • Proximity: elements close together are seen as one group → supports “proximity” design.
  • 相似律（Similarity）：形状 / 颜色相同的元素被归为一类 → 支撑“一致性”。
  • Similarity: elements sharing shape or color are grouped → supports “consistency”.
  • 闭合律（Closure）：大脑自动补全缺口 → 对齐形成的“线”让页面显得完整。
  • Closure: the brain fills in gaps → the “lines” formed by alignment make the page feel complete.

课堂要点：原则不是法律，而是“自查清单”。每次画完布局，用这六条逐项检查，大多数版式问题都能自己发现。Classroom takeaway:Principles are not laws, but a self-review checklist. Run the six items over every layout you draw, and most problems reveal themselves.

关键代码 ① 层级阶梯（type scale）

Key Code ① The Type Scale

层级靠“字号 + 字重 + 颜色”三级叠加，而不是只放大字号。

Hierarchy stacks three levers — size, weight, and color — not just a bigger font.

/* 首屏：主标题 44px 特重，副文 17px 次级色，按钮 14px 加粗高对比 */
.hero h1{font-size:clamp(28px,5vw,44px);font-weight:900}
.hero p{font-size:17px;color:var(--ink-2)}
.hero .btn{font-size:14px;font-weight:700;background:var(--teal);color:#fff}

关键点解释：把“字重 + 颜色”也用上，字号可以不用拉得很大；层级越少越清晰，一页一般只保留 2–3 级（主标题 / 小节 / 正文）。Key point:With weight and color doing part of the work, type sizes stay modest; fewer levels are clearer — usually 2–3 levels per page (headline / section / body).

关键代码 ② 对比度（WCAG）

Key Code ② Contrast (WCAG)

/* 正文与背景的对比率至少 4.5:1，大号文字 ≥3:1 */
--ink:#16261f;   /* 正文 on #fff ≈ 14.2:1，达标 */
--mut:#6d7b75;   /* 弱化文字 on #fff ≈ 4.6:1，达标 */
--line-d:#c3d0ca; /* 只作分隔线，永远不作文字颜色 */

关键点解释：对比度是“对比原则”的硬指标。可以用浏览器 DevTools 的取色器直接查看对比率；弱化文字也别低于 4.5:1。Key point:Contrast is the hard metric of the contrast principle. Check the ratio with DevTools’ color picker; even muted text should stay ≥ 4.5:1.

关键代码 ③ 一致性 token

Key Code ③ Consistency Tokens

/* 把“间距 / 圆角 / 颜色”收进变量，全站只改一处 */
:root{
  --space-1:4px; --space-2:8px; --space-3:16px;
  --space-4:24px; --space-5:32px;
  --radius:10px;
  --teal:#0f766e; --ochre:#c07f22;
}
.btn,.card,.input{border-radius:var(--radius)}

关键点解释：一致性在代码层面就是“不许各自为政”：圆角、阴影、间距全部来自同一组变量，样式自然统一。Key point:Consistency, in code, means “no ad-hoc values”: radii, shadows, and spacing all come from one set of variables, so styles stay unified by construction.

1.3对齐Alignment

网格系统是对齐的落地机制：容器、列、沟槽，让对齐成为默认状态

The grid is alignment’s mechanism: container, columns, gutters make alignment the default

对齐（Alignment）是让所有元素共享同一条基准线的原则——整齐来自“有共同的边”。它的落地机制就是本节的网格系统：把页面切成固定列，元素按列占位，对齐自动完成，无需逐项手调。

Alignment is the principle of sharing baselines — tidiness comes from common edges. Its mechanism is the grid system: slice the page into fixed columns, let elements occupy columns, and alignment happens automatically instead of by hand.

文字对齐：宁左勿乱

Text Alignment: Left Over Chaos

正文默认左对齐（中文阅读方向）；每一列内容共享同一条基准线。居中只用于少量元素（按钮、单行标语），不要整段居中。

Body text is left-aligned by default (the Chinese reading direction); every column shares one baseline. Centering is only for a few elements (buttons, one-line slogans) — never whole paragraphs.

网格的四要素

The Four Parts of a Grid

  • 容器（Container）：内容的宽度上限，常用 960–1440px，居中放置。
  • Container: the max width of content, commonly 960–1440px, centered.
  • 列（Columns）：把容器纵向切成的栏位；元素按“列”来占位，天然对齐。
  • Columns: vertical slices of the container; elements occupy columns, so alignment is automatic.
  • 沟槽（Gutter）：列与列之间的空隙，全站统一（如 16 / 24px）。
  • Gutters: the gaps between columns, uniform site-wide (e.g., 16 / 24px).
  • 外边距（Margin）：容器与视口边缘的留白，随屏幕缩放。
  • Margins: the space between the container and the viewport edge, scaling with the screen.

为什么是 12 列？

Why 12 Columns?

12 能被 2、3、4、6 整除，可以自由组合出 1/2、1/3、1/4、1/6 宽的模块，是“灵活性”与“简单性”的最佳折中。

12 divides evenly by 2, 3, 4, and 6, freely composing 1/2, 1/3, 1/4, and 1/6 width modules — the best trade-off between flexibility and simplicity.

课堂要点：响应式网格 = 在断点处改变“列数”，而不是把整页推倒重排。断点由内容决定（见 1.7），不是照着设备型号抄。Classroom takeaway:A responsive grid changes the number of columns at breakpoints — it does not rebuild the page. Breakpoints follow content (see 1.7), not device names.

关键代码 ① 12 列文章栅格

Key Code ① A 12-Column Article Grid

.posts{
  display: grid;
  grid-template-columns: repeat(12,1fr); /* 12 等分 */
  gap: 24px;              /* 沟槽统一 24px */
  max-width: 1200px;      /* 容器 */
  margin-inline: auto;     /* 外边距自适应居中 */
}
.post{grid-column: span 4}            /* 一行 3 篇 */
.post.featured{grid-column: span 8}     /* 头条占 8 列 */

关键点解释：grid-column: span 4 表示“占 4 列宽”，元素自动贴齐列线，这就是网格让“对齐”变成默认状态的原因。Key point:grid-column: span 4 means “occupy 4 columns”, and elements snap to column lines automatically — that is why a grid makes alignment the default.

关键代码 ② 导航用 Flexbox

Key Code ② Nav with Flexbox

.nav{display: flex;align-items: center;gap: 24px}
.nav .links{display: flex;gap: 16px}
.nav .cta{margin-left: auto}  /* 推到最后侧 */

关键点解释：一条轴上的排布（Logo、链接、按钮）用 Flexbox；margin-left:auto 是把元素推到行尾的惯用技巧。Key point:One-axis arrangement (logo, links, button) uses Flexbox; margin-left:auto is the classic trick to push an item to the end of the row.

关键代码 ③ 断点处改列数

Key Code ③ Changing Column Count at Breakpoints

.post{grid-column: span 4}
@media (max-width: 900px){.post{grid-column: span 6}}  /* 平板：2 列 */
@media (max-width: 600px){.post{grid-column: span 12}} /* 手机：1 列 */

关键点解释：响应式只改“一行的列数”，内容与样式保持不变——栅格替你完成了大部分响应式工作。Key point:Responsiveness only changes the column count per row; content and styles stay put — the grid does most of the responsive work for you.

1.4层级Hierarchy

层级 + 视觉动线：设计“视线先落在哪”，而不是等用户自己找

Hierarchy + visual flow: design where the eye lands first — don’t make the user hunt

层级：四个控制杆

Hierarchy: Four Levers

  • 字号：大 = 先看（主标题最大，正文最小）。
  • Size: big = seen first (headline largest, body smallest).
  • 字重：同字号下，更粗的更强。
  • Weight: at the same size, bolder is stronger.
  • 颜色对比：深色 / 高对比在浅色 / 低对比之前被看到。
  • Color contrast: dark / high-contrast is read before light / low-contrast.
  • 位置与亲密性：顶部与左侧的权重高；孤立的元素更突出。
  • Position & isolation: top and left carry more weight; an isolated element stands out.

动线：用户怎么扫视页面

Flow: How Users Scan a Page

模式特征
PatternCharacteristic
F 型
F-pattern		文本密集型页面：先横读第一行（标题），再横读第二行（摘要），之后沿左侧竖扫。重点放左上，弱化放在右侧与底部。
F-patternText-heavy pages: read the first line (title) across, the second line (summary) across, then scan down the left edge. Put emphasis top-left; de-emphasize right and bottom.
Z 型
Z-pattern		视觉型页面（首屏 / 登录页）：从左上一路到右下，四个角最受关注。把 Logo、CTA 放在两角。
Z-patternVisual pages (hero / landing): from top-left to bottom-right; the four corners get the most attention. Place the logo and CTA at the corners.

嵌入理论：眼球追踪与视觉重量

Embedded Theory: Eye-Tracking and Visual Weight

Nielsen Norman Group 的眼动实验发现：用户以“扫读”为主，约 80% 的时间只花在页面的“F 型”热区上。因此布局的第一任务是让最重要的内容落在热区，而不是要求用户逐字读完。

Eye-tracking studies by the Nielsen Norman Group show users mostly scan: roughly 80% of the time is spent on the “F-shaped” hot zones. The first job of layout is therefore to place the most important content inside the hot zones, not to expect users to read everything.

课堂要点：一页只设计一条主动线：标题 → 摘要 → 行动按钮。动线越多，用户越迷茫。Classroom takeaway:Design one main flow per page: headline → summary → call to action. The more flows you offer, the more lost users get.

关键代码 ① 首屏的完整层级

Key Code ① The Full Hero Hierarchy

.hero{
  display: grid; justify-items: start;      /* 内容整体靠左，符合 F 型 */
  padding: 64px 24px;
}
.hero .eyebrow{font-size: 12px;letter-spacing: 2px;color: var(--ochre)} /* 第 0 级：眉标 */
.hero h1{font-size: clamp(28px,5vw,44px);font-weight: 900}   /* 第 1 级：主标题 */
.hero p{font-size: 17px;color: var(--ink-2);max-width: 36em}  /* 第 2 级：摘要 */
.hero .btn{font-size: 14px;background: var(--teal);color: #fff} /* 第 3 级：行动 */

关键点解释：代码里“层级”体现在选择器顺序与 CSS 数值上：主标题的字号、字重、颜色都要显著大于其它元素；把 CTA 做成唯一的高对比色块。Key point:In code, hierarchy lives in selector order and values: the headline’s size, weight, and color must clearly dominate; the CTA becomes the single high-contrast block.

关键代码 ② 用 max-width 控制行长

Key Code ② Controlling Measure with max-width

/* 正文行长：中文约 34–40 字 / 行，英文 45–75 字符 */
.article p{max-width: 38em}  /* 过长则读起来累，过短则换行频繁 */

关键点解释：全宽正文很难读——限制行长（measure）是文本层级中最容易被忽略的一环。Key point:Full-width body text is hard to read — limiting the measure is the most overlooked part of text hierarchy.

案例首屏 + 扫读热区叠加：切换 F / Z 型查看视线路径；拖动“层级强度”滑块，观察标题与摘要的层级差如何影响首看顺序。

The case hero + scan-heat overlay: switch F / Z pattern to see the reading path; drag the “hierarchy strength” slider and watch how the size gap between title and summary changes what you notice first.

1.5亲密性 · 留白Proximity & Whitespace

空间是有语义的：距离即分组，留白即层级

Space carries meaning: distance groups, whitespace creates hierarchy

间距系统：4 / 8 点基准

The Spacing System: 4 / 8-Point Base

全站间距取 4 或 8 的倍数（4、8、16、24、32、48…）。好处：整除（不同模块对齐顺畅）、节奏一致（视觉上“同一系统”）、改起来快（只调 token，不逐个调）。

All spacing on the site is a multiple of 4 or 8 (4, 8, 16, 24, 32, 48…). Benefits: divisibility (modules align cleanly), consistent rhythm (one visual system), and fast changes (tweak a token, not every rule).

距离即分组（邻近律落地）

Distance Is Grouping (Proximity in Practice)

  • 同一组的元素间距 小（8–16px），组与组之间间距 大（24–48px）。
  • Elements in one group get small gaps (8–16px); groups get large gaps (24–48px).
  • “间距相等”是新手最常见的错误：它抹掉了分组信息，让页面变成一锅粥。
  • Equal spacing everywhere is the classic beginner mistake: it erases grouping and turns the page into mush.
  • 当间距本身足够表达分组时，就可以少画分割线。
  • When spacing already expresses grouping, you can draw fewer divider lines.

留白：不是浪费，是结构

Whitespace: Not Waste, But Structure

留白把内容“托”出来：更大的内边距让卡片更聚焦；区块之间的大留白提示“新段落开始了”。高级感的来源之一就是“敢留白”。

Whitespace lifts content out: larger padding focuses a card; generous gaps between blocks signal “a new section starts”. One source of premium feel is daring to leave space.

课堂要点：亲密性靠“距离差”实现——组内近、组间远；留白则是结构的一部分，不是浪费。二者共同决定页面“干不干净”。Classroom takeaway:Proximity works through distance — close inside a group, far between groups; whitespace is structure, not waste. Together they decide whether a page looks clean.

关键代码 ① 间距 token

Key Code ① Spacing Tokens

:root{
  --s-1:4px;  --s-2:8px;  --s-3:16px;
  --s-4:24px; --s-5:32px; --s-6:48px;
}
.card{padding: var(--s-3);gap: var(--s-2)}
.section{margin-block: var(--s-6)} /* 区块间用最大档 */

关键点解释：只定义 6 个档位，强迫自己“从系统里选”，而不是随手写 13px / 27px。Key point:Define only six steps, forcing yourself to “choose from the system” instead of typing ad-hoc 13px / 27px values.

关键代码 ② margin 还是 padding？

Key Code ② Margin or Padding?

/* padding = 容器内部（内容与边框之间） */
.card{padding: 24px; border: 1px solid var(--line)}

/* margin = 元素之间（外部空间，不画进卡片） */
.card + .card{margin-top: 16px}
/* 或用 flex/grid 的 gap，更推荐 */

关键点解释：凡是“元素之间的距离”优先用 gap 或 margin；“内容与自身边框的距离”用 padding。用反了会出现间距叠加、背景漏色等怪问题。Key point:Distances between elements use gap or margin; the distance between content and its own border uses padding. Reversing them causes doubled gaps and bleeding backgrounds.

关键代码 ③ 垂直节奏

Key Code ③ Vertical Rhythm

/* 行高统一为基础单位，让段落与标题的“底线”落在同一节奏上 */
body{line-height: 1.8}
h1,h2,h3{line-height: 1.35; margin-block: 1.2em .5em}

关键点解释：用 em 做标题间距，字号变化时间距自动成比例，垂直方向读起来有“呼吸感”。Key point:Use em for heading margins so spacing scales with type size — the vertical rhythm breathes on its own.

两组共八张栏目卡：拖「组内间距」与「组间距」制造距离差——组内近、组间远，分组才成立；拖「内边距」观察留白。下方是 4/8 点间距标尺。

1.6对比 · 一致性Contrast & Consistency

对比让主角跳出来，一致性让全站像“一家人”

Contrast makes the hero stand out; consistency makes the whole site feel like one family

对比：让最重要的东西跳出来

Contrast: Make the Most Important Thing Pop

  • 对比的三板斧：字号差（标题大、正文小）、字重差（900 vs 400）、颜色差（强调色 vs 正文色）。
  • Three levers of contrast: size (big headings, small body), weight (900 vs 400), and color (accent vs body).
  • 对比也是无障碍要求：正文与背景对比度应达到 WCAG 4.5:1（1.8 的“无障碍审查”会自动检测）。
  • Contrast is also an accessibility requirement: body text should hit WCAG 4.5:1 against its background (the A11y Audit in 1.8 checks it automatically).
  • 原则：每屏只有一个主角——如果什么都强调，就什么也没强调。
  • Rule: one hero per screen — if everything is emphasized, nothing is.

一致性：复用，而不是重新设计

Consistency: Reuse, Don’t Redesign

  • 同类元素用同一套 token：同一种圆角、同一种间距、同一种按钮样式（圆角 / 颜色 / 字号全相同）。
  • Same-kind elements share one set of tokens: the same radius, the same spacing, the same button style (radius / color / size all identical).
  • 一致性来自“改一处，处处变”——1.8 的 Design Token 编辑器就是它的实时演示。
  • Consistency means “change once, changes everywhere” — the Design Token editor in 1.8 is its live demo.

课堂要点：对比决定“先看什么”，一致性决定“越看越顺”。拾味山居的 CTA 用赭黄强调色（对比），所有卡片共用同一套 token（一致性）。Classroom takeaway:Contrast decides what you see first; consistency makes it feel right. On Shiwei Mountain House the CTA uses ochre (contrast) and every card shares one token set (consistency).

关键代码 ① 对比：字号 / 字重 / 强调色

Key Code ① Contrast: Size / Weight / Accent

/* 层级拉开：标题大而重，正文小而弱 */
.hero h1{font-size: clamp(28px,5vw,48px);font-weight: 900}
.hero p{color: var(--ink-2)}        /* 正文弱化，衬托主角 */
.cta{background: var(--ochre);color: #fff} /* 唯一的强调色按钮 */

关键点解释：对比不是“加一条边框”，而是靠字号、字重、颜色三个维度的差距；三个维度同时拉开，主角才真正跳出来。Key point:Contrast is not “adding a border” — it comes from the gap in size, weight, and color; pull all three apart and the hero truly pops.

关键代码 ② 一致性：token 复用

Key Code ② Consistency: Token Reuse

:root{
  --radius: 8px;  --space: 16px; --teal: #0f766e;
}
.card,.btn,.input{border-radius: var(--radius)} /* 一个圆角，处处一致 */
.card{padding: var(--space)}  /* 一个间距，处处一致 */
/* 改 :root 一处，全站同步 —— 一致性是“设计系统”的雏形 */

关键点解释：一致性 = 拒绝“每次重新设计”。把圆角、间距、颜色定义成变量并复用，组件之间自然长得一样。Key point:Consistency = refusing to redesign each time. Define radius, spacing, and color as variables and reuse them — components naturally look alike.

同一组菜品卡：分别切换「对比」与「一致性」两个开关，看清晰与混乱如何产生。

1.7响应式布局Responsive Layout

移动优先：内容不变，布局渐进增强

Mobile-first: content stays, layout progressively enhances

三个关键策略

Three Key Strategies

  • 移动优先（Mobile-first）：先设计最小的屏（一列、内容最简），再用媒体查询“加宽”。好处是天然内容优先，代码也更少。
  • Mobile-first: design the smallest screen first (one column, minimal chrome), then add width with media queries. It keeps content first by construction, with less code.
  • 断点按内容定：在“内容开始变形 / 挤在一起”的位置设断点（常见 600 / 900 / 1200px），而不是照抄设备型号。
  • Breakpoints follow content: set breakpoints where content starts to squeeze or break (commonly 600 / 900 / 1200px), not by copying device names.
  • 流式单位：布局用 % / fr，字号用 clamp()，图片用 max-width:100%——让元素自己适应，而不是全靠断点。
  • Fluid units: layout in % / fr, type in clamp(), images at max-width:100% — let elements adapt by themselves instead of relying on breakpoints alone.

导航的响应策略

Responsive Nav Strategies

策略适用

链接收进菜单（汉堡）导航项多（≥5）：小屏时折叠成按钮，展开后纵向排列。

嵌入理论：渐进增强 vs 优雅降级

Embedded Theory: Progressive Enhancement vs Graceful Degradation

响应式的核心思想是渐进增强：先保证“最小设备可用”，再为更宽的屏幕增加体验。这比“先做桌面版，再慢慢砍掉”的优雅降级更健壮——内容永远不会因为屏幕小而被牺牲。

Responsive design is built on progressive enhancement: make the smallest device usable first, then add experience for wider screens. That is more robust than graceful degradation — content is never sacrificed for a small screen.

课堂要点：响应式不是“缩放页面”，而是“重新编排布局”。用 1.3 的网格改列数，用 1.5 的间距改密度，大多数页面 3 个断点就够。Classroom takeaway:Responsive is not “zooming the page” but “re-choreographing the layout”. Change column counts with the 1.3 grid, adjust density with the 1.5 spacing — three breakpoints cover most pages.

关键代码 ① 断点改栅格

Key Code ① Breakpoints Change the Grid

/* 基础 = 手机（一列），向上增强 */
.cards{display: grid;grid-template-columns: 1fr;gap: 16px}
@media (min-width: 640px){ .cards{grid-template-columns: repeat(2,1fr)} }   /* 平板 2 列 */
@media (min-width: 1024px){ .cards{grid-template-columns: repeat(3,1fr)} } /* 桌面 3 列 */

关键点解释：用 min-width 从窄到宽写，基础样式就是手机样式——符合移动优先。Key point:Write with min-width from narrow to wide, so the base styles are the mobile styles — that is mobile-first.

关键代码 ② 流式字号 clamp()

Key Code ② Fluid Type with clamp()

/* clamp(最小值, 随视口变化, 最大值)：字号自己伸缩 */
.hero h1{font-size: clamp(28px, 5vw + 8px, 44px)}

关键点解释：流式字号在断点之间平滑过渡，避免“断点一过就跳变”；vw 单位让字号跟随视口。Key point:Fluid type transitions smoothly between breakpoints instead of jumping; the vw unit ties the size to the viewport.

关键代码 ③ 小屏导航

Key Code ③ Small-Screen Nav

.nav .links{display: none}                       /* 手机：先藏 */
.nav .menu-btn{display: block}                    /* 汉堡按钮 */
@media (min-width: 768px){
  .nav .links{display: flex}
  .nav .menu-btn{display: none}
}

关键点解释：“内容隐藏再按需显示”是小屏导航的标准做法；别忘了为菜单按钮提供真实的展开 / 收起逻辑。Key point:“Hide first, reveal on demand” is the standard small-screen nav pattern; remember to give the menu button real open/close behavior.

视口切换器：点击按钮把“迷你站点”缩放到手机 / 平板 / 桌面宽度，观察栅格与导航如何重新编排（纯 JS 重排，容器尺寸即视口）。桌面 1200 超出预览区时，可横向滚动查看完整视图。

Viewport switcher: click to scale the mini-site to phone / tablet / desktop widths and watch the grid and nav re-choreograph (pure JS reflow — the container width is the viewport). When Desktop 1200 overflows the preview, scroll horizontally to see the full view.

1.8案例组装Case Assembly

把 1.1–1.7 全部应用到「拾味山居」首页：原则标注每一处落点

Apply 1.1–1.7 to the “Shiwei Mountain House” homepage: every principle annotated at its spot

组装顺序：骨架 → 层级 → 间距 → 响应式

Assembly Order: Skeleton → Hierarchy → Spacing → Responsive

  1. 骨架（1.1 / 1.3）：导航、首屏、栏目、文章、页脚，套上 12 列栅格。
  2. Skeleton (1.1 / 1.3): nav, hero, sections, articles, footer — on a 12-column grid.
  3. 层级（1.2 / 1.4）：给每个区块定 2–3 级字号，确定唯一 CTA。
  4. Hierarchy (1.2 / 1.4): give each block 2–3 type levels and one clear CTA.
  5. 间距（1.5）：用 4/8 点系统统一内边距与区块间隙。
  6. Spacing (1.5): unify padding and section gaps with the 4/8-point system.
  7. 响应式（1.7）：三个断点重排栅格与导航。
  8. Responsive (1.7): three breakpoints re-arrange grid and nav.

关键点解释：把容器、沟槽、间距全部声明为变量，整个案例的“节奏”由这 5 行决定——这就是一致性在代码里的样子。Key point:Declare container, gutter, and spacing as variables — five lines set the whole case’s rhythm. That is what consistency looks like in code.

反着学最快：在一份“故意做坏”的迷你首页里，亲手抓出 6 处布局罪行

Learn by the negative: catch six layout crimes in a deliberately broken mini homepage

为什么「找茬」比「照着做」更有效

Why Spotting Crimes Beats Copying Perfection

说出「哪里好看」不难，难的是一眼看出「哪里不对」。审查式阅读（critique）是设计师的核心练习：把 1.2 的六条原则倒过来，就是六种典型的「布局罪行」。能在别人的页面里 3 秒内指认罪行，你自己的页面才不会犯同样的错。

Saying what looks good is easy; seeing what is wrong at a glance is the real skill. Critique is a core designer exercise: invert the six principles of 1.2 and you get six classic layout crimes. If you can spot them in someone else's page within three seconds, you won't repeat them in your own.

现场还原：罪行代码 vs 修复代码

Reconstruction: Crime CSS vs Fixed CSS

/* ✕ 现场版：六宗罪齐发 */
.cp-title{font-size:15.5px;font-weight:400}   /* 层级塌陷 */
.cp-center{text-align:center}                  /* 对齐混乱 */
.cp-faint{color:#c9d3cd}                        /* 对比不足 ≈2.1:1 */
.cp-cta{margin-top:34px}                        /* 亲密性断裂 */
.cp-card{padding:2px 3px}                       /* 留白不足 */
.cp-b1{border-radius:2px} .cp-b2{border-radius:999px}
.cp-b3{border-radius:12px}                      /* 一致性破坏 */
/* ✓ 修复版：六条原则各归其位 */
.cp-title{font-size:22px;font-weight:900}     /* 层级：2–3 级字号差 */
.cp-center{text-align:left}                     /* 对齐：全站左基准线 */
.cp-faint{color:#4a5a53}                        /* 对比：≥4.5:1 */
.cp-cta{margin-top:8px}                         /* 亲密性：相关 ≤8px */
.cp-card{padding:14px}                          /* 留白：呼吸空间 */
.btn{border-radius:6px}                         /* 一致性：单一按钮样式 */
/* 全部来自同一套 token —— 见 1.8 的编辑器 */

关键点解释：修复没有魔法：每宗罪对应一个 CSS 属性改动，背后是同一条原则。对照 1.2 的清单逐条“对号入座”，就是一次完整的布局审查。Key point:Fixing is not magic: each crime maps to one CSS property backed by one principle. Matching them one by one against the 1.2 checklist is a full layout audit.
